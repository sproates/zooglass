# Vehicle demo cleanup acceptance

The demo releases its owned resources on normal exit, interruption and Reset.
This review recommends accepting process cleanup for the current bounded demo.
Reviewed source: `7e1e03ad42e615814dca4c4f0e9cb4df1016bedd`, after
[PR #70](https://github.com/sproates/zooglass/pull/70). No implementation changes
were needed during this review.

## Ownership and shutdown

[`vehicle-run.ts`](../../incubator/workbench/src/demos/vehicle/vehicle-run.ts)
closes the scenario, then the browser, then ZooGlass. It attempts later cleanup
even if an earlier close fails. Scenario closure cancels active execution and
waits before disposing of its source sockets and client executors.

[`browser-session.ts`](../../incubator/workbench/src/browser/browser-session.ts)
owns Chromium and the local browser host. It closes the browser process, with a
five-second forced fallback, then closes the host. The
[service owner](../../incubator/workbench/src/service/zooglass-session.ts)
terminates its Maven/JVM process group on POSIX, or its process tree on Windows,
waits for closure and removes the temporary view configuration. Close operations
are idempotent. Reset waits for the old run's cleanup before acquiring a new one.

These boundaries are unchanged; the existing source maps still describe them.

## Verification on macOS

Run on 26 October 2026 with Node 26.0.0, JDK 25.0.5.0.2 and headless Chromium.

| Check | Result |
| --- | --- |
| `npm run test:resources` from Workbench | Both workloads passed: 50 reconnects with bounded bursts, and five complete browser runs with repeated Reset. |
| `npx tsx --test test/zooglass-session.test.ts test/scenario-session.test.ts` | All 11 checks passed, including forced service termination, failed startup, temporary configuration removal, cancellation and partial setup cleanup. |
| CLI `quit` after the first checked source event | Exit 0; all seven captured runner/service/browser processes gone; both service and host ports refused connections and could be rebound; temporary view configuration removed. |
| CLI `SIGINT` during an active data fault | Same cleanup results, while the client was waiting to recover. |
| CLI `SIGTERM` during an active data fault | Same cleanup results, while the client was waiting to recover. |
| Restart between CLI probes | Each new session returned 404 for the vehicle view before its first event, then processed the scenario successfully. |

The external CLI probe launched the real entry point with
`node --import tsx src/demos/vehicle/demo.ts vehicle-tracker --headless --fault`.
It waited for readiness, typed Step commands and waited for their checks. Normal
quit followed the first step; signal exits followed the sixth checkpoint, after
a refused retry. Signals were sent to the CLI process, leaving it responsible
for closing its owned descendants.

Before each exit, the probe captured the runner's process descendants through
`ps`, confirmed Java and Chromium were present, and recorded the service/host
ports and newly created view-configuration directory. After exit it checked that
those PIDs were absent, both ports were reusable and the configuration directory
was gone. It did not kill unrelated processes or infer cleanup solely from the
runner's exit code.

The repeated-reset workload independently checks old pages and browsers close,
old host/service endpoints stop responding, progress returns to zero and the
new vehicle view is absent before source delivery. The reconnect workload checks
consumed receipt buffers and removal of caller abort listeners.

## Scope and remaining work

The [implementation CI run](https://github.com/sproates/zooglass/actions/runs/40407439872)
also passed native macOS and Windows resource workloads. The OS-level signal and
PID inspection above was local macOS evidence, not a Windows signal test.
Forced service shutdown uses a controlled stubborn-process fixture; the real
service and browser exited normally in these probes. This does not claim cleanup
after an uncatchable kill of the orchestrator, operating-system crash or power loss.

The separate change to launch tests from prebuilt ZooGlass remains outstanding;
this review leaves Maven startup unchanged. Final usability, capability claims
and the lasting architecture explanation still need acceptance. This
root-documentation-only change does not trigger Workbench CI.
