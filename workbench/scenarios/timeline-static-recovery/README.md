# Authored static recovery witnesses

These complete V4 documents retain explicit expected values, receipts and snapshots.
They extend the independently authored kiln mixed-mode witness with recovery
checkpoints; expectations are not generated by executing ZooGlass. Unspecified
freshness keeps received-at timestamps null, including after recovery.

| Case | Purpose                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------- |
| M1   | Memory orderly restart, empty state, reconnect baseline and exact reapplication                               |
| M2   | Memory abrupt stop/start at one timestamp with explicit later reconnection                                    |
| S1   | SQLite orderly recovery across two views, original duplicate receipt                                          |
| S2   | SQLite abrupt recovery followed by older input that changes arrival/history but not latest                    |
| S3   | Two SQLite restarts, retained lower-edge duplicate, identity conflict and below-floor rejection               |
| B1   | Maximum static shape: three configured sources, two views and four fields, with aliases and multiple entities |

Each directory contains ordinary runtime JSON and a scenario hashing its exact
bytes. Full receipts retain cumulative history. Recovery snapshots are checked
before new input. Fixtures are deliberately explicit artifacts for review, not
runtime-derived baselines. B1 reaches the admitted shape; it is not a throughput
or maximum-load test.

S2's final frame is version 6: sequence 9 replaces arrival and joins history,
while latest stays at sequence 12. S3's sequence 31 advances the admission floor
to 12 and produces version 6; its next subscription returns that same version.
The retained duplicate and two rejected publications emit no further view update.
Final cumulative frame assertions cover those boundaries, and S3 also compares
the complete installed snapshot after the rejections with its recovered snapshot.
